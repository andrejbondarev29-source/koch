# BRANCH_CONTEXT.md — ветка `assets-storage`

> Контекстный файл для AI-агентов и нейросетей. Дополняет корневой `AGENTS.md` и
> действует **только в ветке `assets-storage`**. При конфликте правил действует более
> строгое; прямое явное указание пользователя важнее любого пункта ниже.

## 1. Роль ветки

`assets-storage` — ветка-склад для хранения тяжёлых ассетов DvorFight: медиафайлов,
графики, спрайтов, фонов, шрифтов, исходников дизайна, аудио и прочих ресурсов проекта.
Ветка **не предназначена для основного исходного кода**: здесь нет места игровой логике,
балансу, UI-коду и сборке. Её задача — хранить, упорядочивать и версионировать ресурсы,
которые слишком велики или неуместны в ветках с кодом.

Код в этой ветке не развивается. `main` остаётся единственным источником истины для
исходников; `assets-storage` — вспомогательное хранилище ресурсов.

## 2. Типовые задачи этой ветки

- Добавление новых тяжёлых ресурсов: PNG-спрайты и фоны, TTF/OTF-шрифты, PSD/AI/Krita
  исходники, видео, аудиосэмплы, референсы.
- Упорядочивание структуры каталогов и имён файлов на складе.
- Ведение манифеста ассетов: что это, откуда, лицензия, размер, где используется.
- Подключение и сопровождение Git LFS для файлов, превышающих разумный размер.
- Оптимизация/сжатие ресурсов вне репозитория с публикацией уже готового результата.
- Добавление превью и описаний, чтобы человеку было понятно содержимое склада.
- Замена устаревшего ассета — только по явной просьбе и с фиксацией причины.

## 3. Что здесь разрешено

- Добавлять новые файлы ресурсов в специально отведённые каталоги склада.
- Создавать и обновлять `README.md`/манифест ассетов, файлы лицензий и атрибуции.
- Настраивать `.gitattributes` для Git LFS, если это требуется для тяжёлых файлов.
- Переименовывать и раскладывать по папкам **собственные добавленные** файлы склада.
- Оптимизировать размер ресурсов (сжатие, приведение к нужному формату) при условии,
  что визуальное качество не страдает и результат проверен глазами.
- Удалять временные рабочие файлы до коммита.

## 4. Что строго запрещено

- Добавлять или менять исходный код: `*.cs`, `DvorFight.csproj`, `build.cmd`, `run.cmd`,
  скрипты сборки и любые файлы, влияющие на поведение игры.
- Менять `Config/Balance.cs`, `AI/BotDifficultyProfile.cs`, геймплей, UI и вёрстку.
- Менять `AGENTS.md` и `.clinerules` — это делается в `main` отдельной задачей.
- Удалять, перезаписывать или «улучшать» существующие ассеты без явного разрешения
  пользователя: склад хранит историю, а не редактируется вслепую.
- Хранить секреты, токены, ключи, персональные данные и чужие файлы без лицензии.
- Коммитить `bin/`, `obj/`, `.vs/`, кэши, логи и временные кропы.
- Дублировать в репозитории большие файлы, которые уже лежат на складе, без причины.
- Делать `git push` в `main`, `force-push`, переписывать опубликованную историю.
- Смешивать добавление ассетов с правками кода или документации вне склада.

## 5. Правила хранения

- **Имена:** латиница в нижнем регистре, слова через дефис, без пробелов и кириллицы;
  версия — суффиксом (`background-arena-v2.png`), а не «final-final».
- **Структура:** группировать по типу и назначению (например, `sprites/`, `backgrounds/`,
  `fonts/`, `audio/`, `source/`, `references/`); не сваливать всё в корень.
- **Форматы:** для рантайма — только те, что поддерживает проект (PNG, TTF); исходники
  дизайна (PSD, Krita, AI) — отдельно от рантайм-файлов.
- **Размер:** всё, что заметно утяжеляет клон, — через Git LFS; перед добавлением
  проверять размер и необходимость файла.
- **Лицензии:** для каждого внешнего ресурса фиксировать источник и лицензию в манифесте;
  без подтверждённой лицензии ресурс не коммитить.
- **Манифест:** каждое добавление отражать в `README.md` склада или отдельном
  `ASSETS.md`: имя, назначение, размер, лицензия, где используется.
- **Проверка:** изображения и шрифты открывать глазами; битые и нечитаемые файлы не
  коммитить.

## 6. Обязательный порядок работы

1. `git fetch origin`; ветка создаётся/обновляется от актуальной `main`:
   `git checkout -b assets-storage main` или `git merge main`.
2. Убедиться, что добавляемый ресурс действительно относится к складу и не должен жить
   в ветке с кодом.
3. Проверить имя, формат, размер, лицензию; при необходимости подключить LFS.
4. Обновить манифест/README склада.
5. Проверить `git diff --check`, `git status`, `git diff --cached --stat` — в индексе
   только ресурсы и их описание, без артефактов и кода.
6. Коммит в стиле `assets(scope): ...` (императив, по-русски).
7. `git push -u origin assets-storage`.

## 7. Definition of Done для этой ветки

- [ ] В коммите только ассеты и их описание; кода и конфигов сборки нет.
- [ ] Имена и структура каталогов соответствуют правилам склада.
- [ ] Тяжёлые файлы добавлены через Git LFS (если применимо).
- [ ] Для внешних ресурсов указаны источник и лицензия.
- [ ] Манифест/README склада обновлён.
- [ ] Существующие файлы не удалены и не перезаписаны без разрешения.
- [ ] Ветка запушена в `origin`; `main` не изменён.

## 8. Связь с другими ветками

- `main` — исходный код и эталон проекта; сюда ресурсы попадают только осознанно и
  небольшими порциями, если они нужны рантайму.
- `testing` — проверка кода, а не хранение медиа.
- `staging` — подготовка выпуска; тяжёлые исходники здесь не хранятся.

Если задача требует изменить код, чтобы использовать новый ассет, — это отдельная задача
в ветке от `main`, а не правка в `assets-storage`.
